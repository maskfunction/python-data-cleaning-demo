JSONL 日志清理与坏记录隔离 — 自建演示

本目录是自行构造的能力样例，不是客户委托、客户数据或成交案例。
没有收入记录，也不暗示已完成任何付费订单。
代码和说明使用 AI 辅助编写，并在本机实际执行下述验证。

适合的问题
一个脚本因为 JSONL 中夹着坏记录而整批中断。这里逐行检查 UTF-8 JSON
对象，输出可继续读取的对象流，并把需要人工确认的记录单独保留。
不猜测缺失字段，不自动补齐截断内容，不悄悄舍弃同名键。

演示结果
sample/input.jsonl 含 8 行自造数据，包括中文、坏 JSON、重复键、空行、
损坏编码、NaN、数组，以及没有末尾换行的合法对象。
运行后的 result/ 含 2 条合法对象、6 条隔离记录。
原文件每个字节都保存在 input.original；每行都有行号、字节位置和 SHA-256。
verification.json 是验证程序实际运行的输出；可重新运行复核。

运行环境
Python 3.10 或更新版本。仅用标准库，无需安装包、联网或购买 API。

在本目录运行
python repair_jsonl.py sample/input.jsonl new-output
python verify_demo.py

new-output 必须是尚不存在的目录。已有目录会被拒绝，不覆盖文件。
退出码 0 表示整个检查已完成，即使存在隔离记录；退出码 2 表示运行失败。
只有 summary.json 的 complete 为 true 且没有 INCOMPLETE.txt 才算完整交付。

输出说明
clean.jsonl       可解析的 JSON 对象，每行一条，统一为 UTF-8 / LF。
rejected.jsonl    坏记录的原因与原始字节 Base64，可准确恢复，不是乱码替换。
audit.jsonl       每个输入物理行的去向、原始位置、哈希与输出行号。
input.original   本次读取输入的逐字节副本，保留原始空格、换行与损坏字节。
summary.json     记录数、原因分类、输入哈希与完成状态。

范围与限制
一行只接受一个 JSON 对象。合法数组、字符串等也会隔离，这是交付范围。
只接受 UTF-8；文件起始 BOM 可以识别。不是任意编码转换器。
普通小数经 Python 浮点解析后输出，表示形式可能变化；精确财务小数、
极高精度数字需另约规则，不能把本样例直接用于那类数据。
整数保留 Python 支持范围内的精确值；NaN、Infinity、溢出数值被隔离。
按物理行读取，内存占用取决于最长单行；不承诺巨型单行的处理能力。
原始副本和隔离文件可能含敏感数据，应与输入享有相同访问权限。
只做确定性检查和隔离；跨行 JSON 重组、业务字段纠错、数据库接入不包含。
这份小样例不是通用修复器，也没有经过生产环境或大规模数据验证。
